# 场景功能化正文生成协议（Scene-Functional Writing Protocol）

本规范用于指导正文章节的推进生成，确保剧情推进与长程叙事记忆的一致性，严禁注水与无效描写。

---

## 一、 分层上下文架构（Tiered Context Architecture）

为了防止长篇连载（50~100+ 章）中模型遗忘设定、道具漂移或上下文 Token 爆炸，生成正文时采用三层上下文协议：

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. HOT Context (当前章节卡点 - 实时强加载)                   │
│    • 当前章节事件细纲 (03_分卷主线与黄金三章细纲.md)         │
│    • 目标作者的 Writing-DNA.md / 语言DNA.md                │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│ 2. WARM Context (最近状态与活跃线索 - 按需加载)              │
│    • 最近 3~5 章滚动微观摘要 (04_伏笔与状态追踪表.md)        │
│    • 当前活跃伏笔清单 (Open 状态的 Foreshadow 列表)         │
│    • 主角当前物理坐标、随身道具余额与身体状态                │
└──────────────────────────────┬──────────────────────────────┘
                               │
┌──────────────────────────────▼──────────────────────────────┐
│ 3. COLD Context (全书背景设定集 - 索引式存档)               │
│    • 01_世界观与战力体系.md                                  │
│    • 02_核心角色档案与声纹表.md                              │
└─────────────────────────────────────────────────────────────┘
```

---

## 二、 场景功能判定法则（The 7 Dimensions）

每一个正文小节（Scene/Beat）**必须实质改变以下 7 项中的至少一项**：

1. **风险（Risk）**：危险升级、底牌暴露、退路被切断，或危机暂时解除。
2. **信息（Information）**：主角获知关键情报、识破敌人伪装，或读者获知重要伏笔。
3. **关系（Relationship）**：结盟、决裂、信任加深、威名树立、产生猜忌。
4. **资源（Resources）**：获得功法/灵石/法宝，或消耗了保命底牌（需即时扣除）。
5. **抉择（Decision）**：主角做出了不可逆的关键选择（如放弃逃跑选择迎战）。
6. **行动（Action）**：执行了具有实际影响的操作，而非原地打转。
7. **读者理解（Reader Comprehension）**：世界观谜团揭开一块，或产生强烈的好奇心。

> **红线警示**：如果一个小节写完了，以上 7 项全无变化，该小节定义为**“无效注水”**，必须重写或删除！

## 三、 DNA 注入与声纹咬合规范

在生成正文时，必须将大纲剧情与 `Writing-DNA.md` 和角色声纹进行咬合：

1. **叙述层（Narration）**：统一遵循 `Writing-DNA.md` 的句长呼吸感与环境白描质感；
2. **对白层（Dialogue）**：严格匹配 `02_核心角色档案与声纹表.md` 中每个角色的专属语言声纹（主角果决克制、反派居高临下、配角幽默碎嘴）；
3. **动作展示优先（Show, Don't Tell）**：
   - ❌ 抽象告知：“他非常愤怒，恨不得杀了对方。”
   - ✅ 具体展示：“他手掌按在剑柄上，指节因为过度用力而微微发白，指缝间隐隐透出森寒的青光。”
4. **伏笔埋设与回收**：
   - 若本章计划埋设新伏笔，必须生成一条带 ID 的伏笔记录（`FB-xxx`）登记到 `04_伏笔与状态追踪表.md`；
   - 若本章回收了历史伏笔，必须将其状态更新为 `已回收 (Closed)`。
